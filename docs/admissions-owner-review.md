# Проверка поступления владельцем

Вход: **Админка → Проверка выпусков → Поступление — полная проверка**.
Доступ нужен назначенному владельцу, а не любому администратору.

1. Начните новую проверку и запустите тестового абитуриента. Каждая проверка создаёт отдельного кандидата. Кнопка «Продолжить» в истории возвращает прежнего.
2. Проходите девять страниц через «Все страницы и тестовые роли». Другая роль проверяет отсутствие чужих заявок.
3. Нажмите «Оставить замечание», напишите текст, при необходимости уточните вкладку/страну/блок. Прикрепите PNG/JPEG файлом или вставкой из буфера. До отправки виден предпросмотр.
4. Нажмите «Сохранить замечание». Дождитесь номера. При сбое сохранённый черновик можно отправить повторно: номер запроса предотвращает дубли.
5. Вернитесь владельцем: замечания видны в очереди вместе с изображениями. Для принятия исправления выполните соответствующий шаг в новой проверке исправленной версии.

## Границы

- Скриншот не снимается автоматически: нужно вставить или загрузить изображение. Поддерживаются PNG/JPEG до 15 МБ на входе; браузер уменьшает размер и сохраняет JPEG до 800 КБ.
- Черновик текста и изображения хранится на текущем устройстве в IndexedDB. После отправки замечание и изображение хранятся на сервере приватно. Очистка данных браузера удаляет неотправленные черновики.
- Непустой черновик остаётся привязан к исходной странице при переходе. Он явно показывает свой адрес. Для новой проблемы отправьте или удалите предыдущий черновик.
- Название вкладки подставляется для страниц с доступной разметкой выбранного элемента; в остальных случаях уточните его в поле «Открытая вкладка или блок».
- Проверяется существующий модуль. Его потеря избранного, текста письма и другие недостатки не исправляются этим режимом и должны попадать в замечания.
- Нет автоматического запуска помощника или публичных ссылок на изображения. Ключ чтения очереди действует семь дней, относится к одному владельцу и может быть отозван.
- Версия проверки должна совпадать с сайтом и сервером. После выпуска новой версии начните новую проверку. Старые замечания сохраняются.

## Передача замечаний помощнику

Кабинет позволяет скачать приватный JSON-отчёт с изображениями или создать ключ чтения.
Храните ключ в локальной настройке окружения, не в чате, исходниках или аргументах команды.
При настроенных `STUDYHUB_REVIEW_API` и `STUDYHUB_REVIEW_KEY`:

```powershell
node scripts/read-review-feedback.mjs
```

Отчёт сохраняется в `.studyhub-local/review-feedback.json`, изображения — в `.studyhub-local/review-evidence/`.
Поле `screenshotFile` связывает замечание с локальным изображением. При ошибке загрузки изображения команда завершается с ошибкой. Папка остаётся приватной и не публикуется.

## Изолированная проверка разработчиком

Сервер использует настоящие обработчики HTTP и проверку прав, но подменённую базу в памяти и тестовый AI. Перезапуск тестового сервера удаляет эти тестовые данные. Производственная база не используется.

В `server`:

```powershell
npm.cmd run test:review
$env:STUDYHUB_TEST_PREVIEW='1'
node --import tsx src/__tests__/review-preview.ts
```

В другой консоли из корня проекта:

```powershell
$env:REVIEW_BUILD_SHA='aaaaaaaa'
$env:VITE_API_URL=''
npm.cmd run dev -- --config scripts/review-vite.config.mts
```

Для автоматического браузерного прохода нужны Playwright в `.studyhub-local/browser-test/node_modules` и установленный Edge:

```powershell
node scripts/admissions-review-browser-check.mjs
```

Для ручного локального просмотра откройте `http://127.0.0.1:4320/__test/login`.
Этот адрес существует только на тестовом сервере. Скрипт браузерной проверки очищает только тестовую очередь перед стартом.

Перед публикацией: перенести только согласованные файлы в `.release-check`, обновить версии, выполнить `check:review` относительно подтверждённого предыдущего рабочего выпуска и пройти сценарий на опубликованной версии. Локальный успех не подтверждает рабочую базу, настройки доступа владельца или подключение очереди на рабочем сайте.
