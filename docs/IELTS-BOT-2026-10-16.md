# IELTS-бот @SkyllaIELTS_bot: локальная реализация и подключение

Владелец создал @SkyllaIELTS_bot в BotFather. @PostFlowEsep_bot предназначен для редактора канала и не используется как ученический бот. Скрипт подключения проверяет точное имя @SkyllaIELTS_bot до любых изменений Telegram.

**Статус: локальные серверная и клиентская сборки прошли; 48 review-тестов прошли, включая 8 IELTS-тестов; targeted ESLint новых IELTS-файлов прошёл.** Прежняя блокировка команд больше не мешает проверкам. `prisma generate` завершился ошибкой EPERM при замене занятого Windows DLL; успешная сборка типов не означает успешную проверку движка Prisma. Миграция не применялась, рабочий сервер не изменён, webhook не подключён. Проверка PostgreSQL и настоящего Telegram остаётся впереди.

Владелец явно выбрал подключение с уже присланным токеном. Токен сохранён в игнорируемом Git файле `server/.env.ielts.local` и в отдельной переменной IELTS рабочего API Railway; значения в отчётах не выводятся. Telegram getMe подтвердил @SkyllaIELTS_bot, getChatMember подтвердил роль administrator в @skyllaAI. Основной бот и PostFlow используют другие настройки.

Без явного `IELTS_TELEGRAM_WEBHOOK_SECRET` setup и сервер получают одинаковый отдельный webhook credential через HMAC-SHA256 с ключом токена и контекстом `studyhub/ielts/webhook/v1`. Сам токен не используется как secret_token. Явный override также поддерживается и должен совпадать в setup и сервере. Локальный override оставлен пустым. Это позволяет не переносить дополнительный секрет через вывод команд. Одна попытка прочитать весь env в вывод была отклонена автоматической проверкой; вместо неё использованы точечная настройка токена через Railway connector и локальное вычисление credential непосредственно перед HTTPS-запросом.

В `.release-check` сформирован отдельный IELTS-выпуск: успешная генерация Prisma 5.22, серверная/клиентская сборки, 44 review-теста до добавления теста HMAC. Дополнительно изолированный PostgreSQL-движок PGlite через TCP и настоящий Prisma Client подтвердили цепочку миграций, сохранение на диск и восстановление после закрытия/открытия БД, rollback, дубликаты, claim доставки, повтор ошибок и изоляцию. PGlite сериализует соединения, поэтому это не доказательство конкурентного поведения нативного PostgreSQL.

Браузерная проверка прошла на изолированном preview `http://127.0.0.1:4334/__test/login`: карточка и запуск роли, отсутствие подписки/ошибка Telegram, цель, неверный ответ, повтор update и старой кнопки, сохранение после перезагрузки, исправление ошибки, смена цели без потери истории, тайм-аут доставки и восстановление, изоляция двух учеников, сохранение замечания, мобильная ширина 390 px без горизонтальной прокрутки. Ошибок JavaScript нет. Скрипт и снимки: `.studyhub-local/ielts-bot-2026-10-16/`. Telegram и хранилище синтетические, данные preview живут до остановки его процесса. Это не проверка PostgreSQL и не приёмка рабочего Telegram-бота.

## Что подготовлено

- Отдельный webhook `/api/ielts-bot/webhook` и отдельный token. Без токена webhook возвращает 503; credential вычисляется или задаётся явно. Конфигурация исключает повторное использование известного рабочего бота и PostFlow.
- Проверка подписки через getChatMember перед учебными действиями. Сетевой сбой не выдаётся за отсутствие подписки. /progress, /help и /privacy доступны без подписки; отписка не удаляет результаты.
- Цель 6.0–8.0 как желание ученика, не диагностика уровня. Изменение цели сохраняет историю и активную попытку.
- Шесть авторских мини-занятий / 12 вопросов Reading и Vocabulary. После каждого ответа — объяснение. Повтор ошибок не переписывает первоначальный результат. Это не официальные экзаменационные задания и не оценка IELTS band.
- Сохранение ответов, незавершённой попытки, очереди ошибок и последних 100 завершённых попыток. Общие счётчики сохраняются. Аккаунт Telegram пока не объединён с аккаунтом сайта.
- Отдельные таблицы IeltsBotAccount/IeltsBotUpdate. Изменение прогресса и запись update выполняются в одной транзакции. Optimistic CAS и ключ account/update защищают от конкурентного зачёта. Доставка имеет отдельный claim; sent фиксируется только с message_id. Неизвестная доставка или остановка после claim не повторяется вслепую. Новый /today восстанавливает задание из сохранённого состояния.
- Сценарий владельца `ielts-bot-v1`, `/ielts-bot-review`: реальные функции бота с синтетическими Telegram и подпиской, отдельные аккаунты на запуск, отзыв через обычную панель. Для локального preview предусмотрен memory adapter; основной сценарий использует отдельные строки БД с префиксом review.
- Восемь тестов поведения в `server/src/__tests__/ielts-bot.test.ts` прошли отдельно и в составе 48 review-тестов.

## До проверки и выпуска

1. В изолированном тестовом окружении выполнить Prisma generate, затем серверную/клиентскую сборку, `npm run test:ielts-bot`, текущие review-тесты, targeted lint.
2. Применить новую миграцию на отдельной тестовой БД. Проверить реальный Prisma CAS при параллельных updates, откате транзакции, остановке сервера, потере receipt и повторном запуске. Memory-тесты не доказывают поведение PostgreSQL.
3. Локальный синтетический сценарий в браузере пройден; повторить приёмку на выпущенной версии с постоянной тестовой БД, проверить свежий запуск/возобновление и привязку feedback к deployed SHA.
4. Завершить процедуры удаления данных по запросу и ограничения злоупотребления. Обработанные updates сейчас сохраняются без автоматической очистки; определить срок хранения, не разрушая защиту от поздних дублей.
5. Через `.release-check` перенести только IELTS-изменения, сохранив отдельно очередь редактора и личный учебный маршрут. В manifest должен быть `ielts-bot-v1`; выполнить `check:review` против предыдущего подтверждённого production SHA. Это не разрешение публиковать непроверенный код.

## Подключение в конце

Бот @SkyllaIELTS_bot уже создан. Токен по решению владельца подключается без перевыпуска и хранится в приватном `server/.env.ielts.local` и настройках Railway. Образец без секретов — `server/ielts-bot.env.example`. Локальный файл сам по себе Railway не настраивает.

Добавить IELTS-бота администратором @skyllaAI: [Telegram гарантирует getChatMember для других пользователей, когда бот является администратором](https://core.telegram.org/bots/api#getchatmember). Права публикации ученическому боту не нужны для этой функции.

После проверенного выпуска и миграции, из папки server:

```powershell
node --import tsx scripts/configure-ielts-bot.ts
# Только после проверки идентичности и целевого канала:
node --import tsx scripts/configure-ielts-bot.ts --apply
```

Первый запуск только проверяет идентичность и права. Второй устанавливает webhook и команды; не сбрасывает накопленные updates. Затем нужна реальная приёмка двух тестовых Telegram-пользователей: подписка/отписка, задания, перезапуск, история, повторные кнопки. Не использовать ученические попытки для тестов.

## Следующие учебные блоки

«Спаси ошибку» — реализованная идея очереди повторений. Далее: Writing с правкой и повторной сдачей, Speaking с голосовым ответом и понятными границами оценки, выбор даты экзамена, добровольные напоминания и недельная сводка. ИИ-оценку не выдавать за официальный IELTS band. Официальные [образцы IELTS](https://ielts.org/take-a-test/preparation-resources/sample-test-questions) используются как ссылка для продолжения, а не копируются в банк.

PostFlow станет отдельным рабочим интерфейсом владельца: прислать материал → исправить → проверить источник → увидеть предпросмотр → подтвердить публикацию. Его токен ещё не подключён, управление через PostFlow этим изменением не реализовано. Веб-кабинет остаётся инструментом проверки реализации.
